# پوشه `src/sql_validation` (SQL Validation & Hardening)

این پوشه وظیفه اعتبارسنجی و ایمن‌سازی کوئری‌های تولید شده توسط LLM را بر عهده دارد. از آنجا که خروجی مدل‌های زبانی غیرقابل اعتماد است، این لایه به عنوان «خط دفاعی» نهایی عمل می‌کند.

## فایل‌ها

- **`validation_pipeline.py`:** ارکستراتور اصلی که تمام اعتبارسنج‌ها را به ترتیب اجرا می‌کند. این ماژول در گره `validate_sql` در گراف LangGraph استفاده می‌شود.
- **`syntax_validator.py`:** بررسی سینتکس SQL با استفاده از `sqlglot`.
- **`safety_validator.py`:** تضمین اینکه فقط دستورات `SELECT` اجرا شوند و از حملات تزریق SQL جلوگیری شود.
- **`schema_validator.py`:** تطبیق کوئری با ساختار دیتابیس (بررسی وجود جداول و ستون‌ها).
- **`join_validator.py`:** بررسی صحت Joinها بر اساس گراف اسکیما.
- **`sql_rewriter.py`:** اصلاحات خودکار و امن (مانند حذف کاراکترهای اضافی یا اعمال محدودیت `LIMIT`).
- **`validation_result.py`:** ساختار گزارش خطاها که به لایه Reflexion برای اصلاح خودکار ارسال می‌شود.

## ویژگی‌های کلیدی
✅ **یکپارچگی با گراف:** خروجی‌های این لایه مستقیماً مسیر گراف را تعیین می‌کنند (اگر خطا باشد، گراف به مرحله تولید بازمی‌گردد).
✅ **سخت‌گیری در امنیت:** هرگونه تلاش برای تغییر داده (DML) یا دسترسی به جداول سیستمی در نطفه خفه می‌شود.
✅ **بازخورد برای اصلاح:** خطاهای تولید شده در اینجا به گونه‌ای طراحی شده‌اند که برای مدل زبانی قابل فهم باشند تا بتواند خودش را اصلاح کند.

*نکته: هیچ کوئری‌ بدون عبور از این فیلترها اجازه ورود به `src/db` را نخواهد داشت.*
